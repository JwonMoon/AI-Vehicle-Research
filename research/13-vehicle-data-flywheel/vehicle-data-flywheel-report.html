요약

핵심 결론 5가지

  1. 성능의 결정 요인이 코드에서 데이터로 이동함. Tesla는 FSD v12에서 도심 주행 스택을 "30만 줄 이상의 C++ 코드를 대체하는 단일 신경망"으로 바꿨다고 릴리스 노트에 명시함 📰. 규칙은 사람이 고치지만 모델은 데이터로만 고칠 수 있으므로, 데이터를 모아 고쳐 배포하는 루프가 곧 개발 방법이 됨.
  2. 사고율은 드문 상황(롱테일)이 좌우함. Waymo의 WOD-E2E 데이터셋은 일상 주행에서 발생 빈도 0.03% 미만 상황만 모은 것임 📰. 도시·날씨·나라가 바뀌면 성능이 떨어지고(분포 변화), 재학습한 모델은 예전에 잘하던 것을 잊음(성능 회귀).
  3. 실도로 주행만으로는 안전을 증명할 수 없음. RAND는 사람보다 안전함을 95% 신뢰로 보이려면 무사고 2억 7,500만 마일이 필요하다고 계산함 📰. 따라서 시뮬레이션과 "계속 도는 폐쇄루프"가 필수임.
  4. 차량 플라이휠은 일반 AI 플라이휠과 여섯 가지가 다름. ① 데이터가 차 안에서 생겨 올릴 수 있는 양이 제한됨 ② 정답이 개입·사고 같은 물리적 결과임 ③ 배포 앞에 안전 인증 관문이 있음 ④ 소프트웨어 업데이트 자체가 규제 절차(UN R156)임 ⑤ 시뮬레이터가 필수임 ⑥ 동의 없는 제3자·위치·지리정보가 얽혀 개인정보·국외 반출 규제를 더 받음(2.3절).
  5. 2021년 "데이터 엔진"과 2026년 플라이휠은 같은 원, 다른 부품임(5.1절). 사람이 짠 트리거 → 임베딩 검색, 사람 라벨링 → 파운데이션 모델 자동 라벨링, 로그 재생 → 3D 재구성·생성형 월드모델, 모방학습 → 폐루프 강화학습, 연 단위 릴리스 → 주 단위 OTA로 이동 중임.

시사점

  • 플라이휠의 경쟁력은 "한 바퀴를 얼마나 자주·싸게·믿을 수 있게 돌리느냐"로 귀결됨. 병목(데이터 발견·검증·비용·규제)이 이 세 변수를 막음.
  • 병목의 위치가 "사람 손"(트리거 작성·라벨링·시나리오 작성)에서 "GPU와 데이터 파이프라인"으로 이동함. 자동 라벨링·재구성·생성이 그 원인임. 어느 회사도 9단계를 전부 남에게 맡기지 않으며, 온보드 선별·학습·배포 책임은 자체로 쥐고 검색·라벨링·시뮬 도구는 사서 씀(4장).
  • 플라이휠의 첫 단계(온보드 선별·섀도 실행)와 마지막 단계(OTA·규제 기록)는 차 안에 있으므로, 차량 HPC 플랫폼 설계 조건이 됨(5.6절).

1. 배경

개요

자율주행에서 데이터 플라이휠이 주목받는 이유를 설명함. 데이터 플라이휠의 개념(1.1), 규칙 기반에서 학습 기반 시스템으로의 진화(1.2), 기존 AI 학습 방식의 네 가지 한계(1.3), 지속적 closed-loop learning의 필요성(1.4) 순서임.

핵심 결론
  1. ①주행 소프트웨어가 사람이 쓴 규칙에서 데이터로 학습한 모델로 바뀌었고, 모델은 데이터가 없는 상황에서는 무엇을 해야 할지 모름.
  2. ②사고를 결정하는 것은 드문 상황이고, 드문 상황은 지역·날씨·차종이 바뀌면 또 달라지며, 새 모델은 예전 상황을 잊을 수 있음.
  3. ③실도로 주행으로 안전을 증명하기엔 필요한 거리가 너무 길므로, "차에서 데이터를 모아 → 고쳐서 → 시뮬레이션으로 확인하고 → 다시 차에 보내는" 루프를 멈추지 않고 돌려야 함.

1.1 데이터 플라이휠의 개념

  • 원뜻: 플라이휠(flywheel)은 무거운 바퀴를 뜻함. 처음 돌리기는 힘들지만 한번 돌면 관성으로 계속 돎.
  • 사업 용례: Amazon의 제프 베조스가 2001년에 그린 선순환 그림이 유명함. 가격을 낮추면 고객이 늘고, 고객이 늘면 판매자와 상품이 늘고, 그러면 고객 경험이 좋아져 다시 고객이 늚 📰 (retaildogma, feedvisor).
  • AI 용례(데이터 플라이휠): 위 그림의 주어를 데이터로 바꾼 것임. NVIDIA 용어집 정의는 "상호작용과 프로세스에서 모은 데이터로 AI 모델을 계속 개선하고, 그 모델이 더 좋은 결과와 더 가치 있는 데이터를 낳는 피드백 루프" 📰 (NVIDIA Glossary).
  • 핵심 ①: 모델을 쓰면서 나온 데이터를 버리지 않고 다시 학습에 씀.
  • 핵심 ②: 그 과정이 한 번이 아니라 계속 반복됨.
  • 자율주행 용례: 같은 말을 "데이터 엔진(data engine)" 또는 "폐쇄루프(closed loop)"라고도 부름.
  • 2024년 학술 서베이의 정의: "(1) 데이터 수집 → (2) 저장 → (3) 선별·전처리 → (4) 라벨링 → (5) 모델 학습 → (6) 시뮬레이션·테스트 검증 → (7) 실세계 배포"의 반복 🔍 (Awesome Data-Centric AD README, 논문 arXiv 2401.12888).
  • 같은 서베이가 산업 사례로 드는 회사: Tesla·NVIDIA·Momenta·Horizon·Baidu·XPeng·Pony.ai·Amazon 등 아홉 개 🔍.
시사점

용어(플라이휠·데이터 엔진·폐쇄루프)는 다르지만 구조는 같음. "쓰면서 나온 데이터를 다시 학습에 쓰고, 이를 반복한다"가 공통 정의임.

1.3 기존 AI 학습 방식의 한계 (데이터 플라이휠이 주목받는 이유)

  • 전제: 학습 기반 시스템은 규칙이 아니라 데이터로만 고칠 수 있음(1.2절). 따라서 문제는 "어떤 데이터가, 왜 부족한가"로 바뀜.
  • 네 가지 한계: 드문 상황이 사고를 좌우하는 롱테일(1.3.1), 장소·날씨가 바뀌면 성능이 떨어지는 분포 변화(1.3.2), 재학습이 예전 능력을 지우는 성능 회귀(1.3.3), 실도로 데이터로는 안전을 증명할 수 없는 문제(1.3.4).
  • 공통점: 넷 다 "한 번 모은 데이터로 한 번 학습해 배포하는" 기존 방식으로는 풀리지 않음. 이것이 데이터 플라이휠이 주목받는 이유임.

1.3.1 롱테일 문제

  • 정의: 주행의 대부분(직진, 차선 유지, 앞차 따라가기)은 평범하고 모델은 금방 배움. 문제는 드물게 일어나는 상황임(공사 구간 콘 옆 작업자, 갑자기 뛰어드는 동물, 비 오는 밤의 역광, 예측하기 어려운 사람의 행동). 이를 롱테일(long tail) 이라 부름. 빈도 그래프의 오른쪽으로 길게 늘어진 꼬리처럼, 각각은 드물지만 종류가 무한히 많음.
  • Waymo WOD-E2E(2025-10): 롱테일을 정면으로 겨눈 데이터셋 📰 (arXiv 2510.26125).
  • 일상 주행에서 발생 빈도 0.03% 미만인 상황만 골라 4,021개 구간(약 12시간)을 모음.
  • 평가 지표를 "기록된 궤적과의 거리"가 아니라 "사람 평가자가 선호한 궤적과의 거리"(RFS, Rater Feedback Score)로 바꿈.
  • 판단 근거: 흔한 상황에서는 이미 잘하므로 드문 상황에서만 모델 간 차이가 드러남.
  • 드문 상황이 안전을 지배하는 이유: 안전 지표 자체가 드문 사건이기 때문임.
  • 미국 사람 운전자의 부상 신고 충돌은 100만 마일당 2.80건 📰 (Waymo 비교 연구).
  • 100만 마일에서 세 번 남짓 일어나는 사건을 줄이려면 99.99%를 잘하는 것으로는 부족하고, 나머지 0.01%에서 무엇을 하는지가 결정함.
  • Elon Musk의 "9의 행진(march of nines)"도 같은 뜻임. 신뢰도 99% → 99.9% → 99.99%로 9를 하나씩 붙일 때마다 남은 예외 상황을 처리해야 하고, 그 예외가 곧 롱테일임 📰 (보도).
시사점

흔한 상황을 더 잘하는 것은 사고율에 거의 기여하지 않음. 플라이휠은 드문 상황을 찾아내고 늘리는 장치여야 함.

1.3.2 데이터 분포 변화

  • 정의: 한 도시에서 배운 모델을 다른 도시에 가져가면 성능이 떨어짐. 이를 분포 변화(distribution shift) 라 함. 학습 데이터와 실제 데이터의 "분포"(어떤 상황이 얼마나 자주 나오는가)가 다르다는 뜻임.
  • 수치로 확인된 사례
사례 내용 근거

시사점

새 시장에 들어갈 때마다 그 시장의 데이터를 모아 넣어야 함. 플라이휠이 지역 확장의 도구가 되는 이유임.

1.3.3 성능 회귀

  • 현상: 모델을 다시 학습시키면 새로 넣은 상황은 좋아지지만 예전에 잘하던 상황이 나빠질 수 있음. 학습 분야에서는 파국적 망각(catastrophic forgetting) 이라 부름. 새 데이터에 맞춰 가중치를 바꾸다가 예전 지식이 덮어써지는 현상임.
  • 연구 근거: 자율주행의 지속 학습에서도 보호 장치 없이 재학습만 하면 망각이 생김 📰 (IEEE).
  • 대응 = 회귀 테스트: 플라이휠에는 회귀 테스트가 반드시 들어감.
  • Tesla의 Andrej Karpathy가 CVPR 2021 발표에서 설명한 데이터 엔진 루프: "섀도 모드로 배포 → 예측을 관찰 → 트리거를 조정해 새 데이터 수집 → 잘못된 예측을 '유닛 테스트'로 만들기 → 비슷한 예제를 데이터셋에 추가 → 재학습 → 반복". 당시 플릿에서 221개 트리거 가동 📰 (발표 요약).
  • 틀렸던 상황을 테스트로 남겨 두면 다음 모델이 그 상황을 다시 틀리는지 확인 가능함.
  • Waymo: 새 소프트웨어를 낼 때마다 "테스트 트랙·실도로·합성 시나리오 전부를 시뮬레이션에서 다시 실행"하고, 충돌 회피 시나리오는 상대 차량의 위치·속도를 조금씩 바꿔 가며(fuzzing) 돌림 📰 (Waymo CAT).
시사점

실패 사례는 한 번 고치고 버리는 것이 아니라 영구 회귀 세트로 축적해야 함. 이것이 5.3절의 회귀 세트임.

1.4 지속적 closed-loop learning의 필요성

  • 1.3의 네 가지 한계를 정리하면 한 방향을 가리킴
압력 무엇이 문제인가 플라이휠이 하는 일
학습 모델 데이터 없는 상황은 못 푼다 실패한 상황의 데이터를 모아 다시 학습
롱테일 드문 상황이 사고율을 결정 드문 상황을 찾아내고 늘려서(합성) 학습
분포 변화 장소·날씨·차종이 바뀌면 성능 하락 새 시장 데이터를 빠르게 모아 적응
성능 회귀·검증 한계 새 모델이 예전 것을 잊고, 실주행으로는 증명 불가 회귀 테스트 세트와 시뮬레이션으로 배포 전 확인
  • 결론: 네 가지를 한 번에 해결하는 방법은 하나임. 차에서 데이터를 모으고, 고쳐서, 시뮬레이션으로 확인하고, 다시 차에 보내는 루프를 계속 돌리는 것임. "데이터 플라이휠"이든 "데이터 엔진"이든 구조는 같음. 그 구조를 2장에서 펼침.
시사점

플라이휠은 선택이 아니라 학습 기반 자율주행의 전제 조건임. 다음 장은 그 단계를 하나씩 펼침.

2. 차량·클라우드·검증 환경을 연결하는 데이터 플라이휠 생태계

개요

차량 데이터 플라이휠의 9단계를 펼치고, 챗봇 같은 일반 AI 플라이휠과 무엇이 다른지를 여섯 가지로 비교함. 2021년 데이터 엔진이 2026년 플라이휠로 어떻게 바뀌었는지는 5.1절에서 다룸.

핵심 결론
  1. ①일반 AI 플라이휠은 "생산 로그 → 데이터셋 → 미세조정 → 평가 → 배포"의 루프이며, NVIDIA가 이를 소프트웨어 블루프린트로 공개함.
  2. ②차량 플라이휠은 여기에 "차 안에서의 선별·업로드", "시뮬레이션 검증", "안전 인증 관문", "OTA 규제"가 끼어들어 원이 더 길고 관문이 더 많음.
  3. ③일반 AI도 개인정보 규제를 받지만, 차량은 동의한 적 없는 제3자를 찍고 위치가 항상 붙으며 도로 영상이 지리정보로 취급되어 국외 반출 규제까지 받음.

2.1 기준점 — 일반 AI 데이터 플라이휠

  • 6단계 — 같은 문서가 "몇 시간 안에 자동으로 한다"고 설명하는 단계 🔍
단계 내용
1 로그 저장소(Elasticsearch)에서 생산 데이터를 가져옴

3 중복 제거
4 클래스별 계층화 분할로 평가용·미세조정용 데이터셋 생성 → 데이터 저장소(NeMo Datastore)에 업로드

  • 승격은 사람 판단: README는 "플라이휠은 자동 조종 장치가 아니라 손전등"이라 쓰고, 제한 사항 문서는 "어떤 모델도 자동으로 승격·배포하지 않으며, 사용자 피드백도 받지 않는다"고 명시함 🔍 (제한 사항, 구조 문서). 여섯 단계는 후보를 찾아 점수를 매기는 데서 끝남.
  • 효과 = 비용 절감(단서 포함)
  • README: "NVIDIA 내부 실험에서 플라이휠로 추론 비용을 최대 98.6% 줄인 사례가 있다" 🔍.
  • 같은 문장의 단서: "이런 사례는 에이전트가 소수의 도구 중 하나를 고르는 단순한 도구 호출 용도에 집중돼 있다" 🔍.

  • 사내 지식 비서 논문(직원 3만 명 이상 사용): 3개월간 부정 피드백 495건을 모아 라우팅 오류 5.25%를 찾아내고, 라우터를 70B 모델에서 미세조정한 8B 모델로 바꿔 정확도 96%·지연 70% 감소 📰 (arXiv 2510.27051).
  • 일반 플라이휠의 세 가지 특징(뒤의 비교 기준)
  • 데이터는 서버 로그에서 공짜로 나옴.
  • 정답(라벨)은 큰 모델의 채점이고, 사람은 결과 검토와 승격만 맡음.
  • 배포는 서버의 모델을 바꾸면 끝남.
시사점

일반 플라이휠의 "98.6% 절감"은 단순 도구 호출을 70B → 1B로 증류한 사례이므로 자율주행에 그대로 적용할 수 없음(5.4절).

# 차이 일반 AI(챗봇·에이전트) 차량(자율주행) 근거
1 데이터가 생기는 곳과 올릴 수 있는 양 사용자가 서버에 접속해 쓰므로 로그가 서버에 저절로 남고, 전부 보관해도 비용이 적음 데이터가 차 안 센서에서 생김. 카메라 원본은 시간당 수십 GB~수 TB라 통신 요금·저장비 때문에 전부 올릴 수 없고, 차 안에서 "올릴 만한 순간"을 골라야 함(3.1절) Tesla HW4 카메라는 시간당 약 20GB 생성(커뮤니티 추정 ⚠️); Mobileye REM은 km당 10KB만 보내도록 설계 📰; comma는 마일당 $0.003 미만으로 서비스 비용을 맞춤 📰
2 정답(라벨)의 성격 사용자 클릭·평점·큰 모델의 채점. 화면 안에서 끝남 운전자 개입, 아슬아슬한 순간(니어미스), 충돌 같은 물리적 결과. 3D 위치·속도처럼 사람이 눈으로 못 만드는 라벨이 많아 자동 라벨링이 필수(3.2절) Tesla 섀도 모드는 모델 출력과 운전자 행동을 비교 📰; NHTSA는 자율주행 충돌을 1~5일 안에 보고하게 함 📰 (SGO 2021-01)
3 배포 앞의 안전 관문 평가 점수가 좋으면 바로 교체 새 모델이 "안전하다"는 논증(안전 케이스)을 표준에 맞춰 다시 써야 함. ISO 26262(고장), ISO 21448(고장이 없어도 성능 한계로 생기는 위험), ISO/PAS 8800(AI 부품의 안전) 📰 (UL 해설)
4 소프트웨어 업데이트 자체가 규제 절차임 하루에도 여러 번 서버의 모델을 바꿈 UN 규정 R156이 요구하는 것: ① 제조사가 업데이트를 관리하는 체계(SUMS)를 인증받을 것 ② 모든 소프트웨어 버전에 식별 번호(RxSWIN)를 붙여 어떤 차에 어떤 버전이 실렸는지 추적할 것 ③ 업데이트가 인증받은 기능에 영향을 주면 다시 승인받을 것 ④ 업데이트 전에 대상 차량과 맞는지 확인하고, 주행 중 안전하게 설치하며, 사용자에게 알리고, 기록을 남길 것. EU는 2024년 7월부터 모든 신차에 적용. 즉 모델을 바꿔 내보내는 행위 자체가 인증 대상이라 "조용히 자주" 바꿀 수 없음 📰 (요약)
5 시뮬레이터가 필수 실제 사용자 일부에게 새 모델을 보여 주는 A/B 테스트로 충분 위험한 상황을 실차로 반복할 수 없고, 실주행 거리로는 안전을 증명할 수 없음(1.3.4절). 시뮬레이션이 검증의 주 수단 Waymo 실주행 2,000만 vs 시뮬 200억 마일 📰
6 개인정보의 범위와 데이터 주권 개인정보 규제(GDPR 등)를 똑같이 받지만, 데이터의 주인은 서비스에 가입하고 약관에 동의한 당사자이고, 데이터는 글·클릭임 같은 규제를 받되 세 가지가 더 붙음. ① 카메라가 동의한 적 없는 제3자(보행자·옆 차 운전자·번호판)를 찍음. EU 개인정보 감독기구(EDPB)는 차 밖의 사람·번호판도 개인정보로 봄 📰 ② 주행 데이터에는 위치·이동 경로가 항상 붙음 ③ 도로·건물·지형 영상은 지리정보로 취급돼 국가 안보 관점의 국외 반출 규제를 받음. Tesla는 중국 도로 데이터를 미국으로 못 보내 상하이에 데이터센터와 학습 인프라를 따로 두었고, 한국은 원본 영상 학습을 규제 샌드박스로만 허용하며 국외 이전은 별개 심사임 📰 (EDPB 가이드라인 1/2020, Electrek 2026-02, 국내 보도, 머니투데이 2026-08)
  • 차이 6 보충 — "얼굴·번호판은 일반 AI에도 있지 않나?"
  • 맞음. 챗봇 로그에도 개인정보가 들어가고 GDPR 같은 규제는 똑같이 적용됨. 차량이 다른 점은 데이터의 종류가 아니라 동의 구조·위치 결합·지리정보 규제 세 가지임.
  • 동의 구조: 챗봇 사용자는 약관에 동의한 당사자이지만, 차가 찍는 보행자와 옆 차 운전자는 동의한 적이 없음. 그래서 EDPB는 차 밖 데이터를 별도 항목으로 다루고 차내 처리(원본을 차 밖으로 내보내지 않음)를 권고함 📰.
  • 위치 결합: 주행 영상은 언제·어디를 지났는지와 함께 기록되므로, 얼굴을 가려도 이동 경로 자체가 개인정보가 됨.
  • 지리정보 규제: 도로·건물 영상은 지도 데이터와 같은 취급을 받음. 중국은 차량 운행 정보의 국외 반출을 원칙 금지하고 평가·보고를 거치게 하며 📰, 한국은 정밀지도 반출을 오래 제한해 왔고 자율주행 영상의 국외 이전은 개인정보위 심사 대상임 📰.
  • 딜레마: 얼굴·번호판을 흐리면 사람·차를 인식하는 학습에 쓸 정보가 사라짐. 한국이 "안전 조치를 조건으로 원본 그대로 학습"을 샌드박스로 허용한 이유임(5.5절).
시사점

일반 플라이휠은 "얼마나 빨리 도는가"의 문제이고, 차량 플라이휠은 "관문을 통과하면서도 계속 돌게 하는가"의 문제임. 2021년 데이터 엔진이 2026년 플라이휠로 어떻게 바뀌었는지는 5.1절에서 봄.

3. 데이터 플라이휠의 작동 방식과 핵심 기술

개요

2장이 플라이휠의 전체 구조(9단계)를 보여 줬다면, 이 장은 그 안에서 실제로 쓰이는 핵심 기술을 네 묶음으로 나눠 봄. ① 데이터 수집·선별(차 안, 단계 ①②) ② 검색·라벨링(클라우드, 단계 ③④) ③ 학습·합성 데이터(클라우드, 단계 ⑤) ④ 검증·배포(단계 ⑥⑦⑧). 각 묶음마다 핵심 원리 → 기술·도구 → 기업 사례 → 3.0절의 가상 사례에 적용 순서로 정리함.

핵심 결론
  1. ①차 안에서는 "요약 로그를 먼저 올리고, 원본은 서버가 지목할 때만 올리는" 두 단계 업로드와 세 종류의 트리거(규칙·모델 점수·사람)가 돎.
  2. ②클라우드에서는 임베딩 검색으로 비슷한 장면을 수백~수천 개 모으고, 온보드보다 훨씬 큰 모델이 미래 프레임까지 보면서 정답을 소급해 붙임.
  3. ③모은 것만으로 부족한 장면은 재생·재구성·생성 세 갈래의 합성 데이터로 늘리고, 시뮬레이터 안에서 정책이 직접 운전하며 배우는 폐루프 학습으로 넘어가는 중임.
  4. ④검증은 하나의 점수가 아니라 개루프 → 폐루프 → 사람 선호 → 회귀 세트 → HIL → 섀도 → 단계적 OTA로 올라가는 사다리이고, 마지막 단(OTA)은 규제 절차임.

4.2 Tesla — 플릿이 곧 센서이고, 9단계를 전부 안에서 돌린다

  • 플라이휠이 도는 순서
  • ① FSD를 켜지 않은 차에서도 백그라운드에서 판단을 내려 실제 운전과 비교하는 섀도 모드가 돌고, 2021년 기준 221개 트리거가 "이 순간을 올려라"를 판단함 📰 (Karpathy CVPR'21 요약).
  • ② 걸리면 약 10초 클립을 올림. 2021년 첫 데이터셋 100만 클립·1.5PB, 2026년 FSD 누적 140억 마일 📰⚠️ (Electrek).
  • ③④ 여러 차의 주행을 합쳐 4D(3D + 시간)로 재구성한 뒤 차선·객체 라벨을 자동 생성. 1만 주행 기준 "수작업 500만 시간 → 클러스터 12시간" 주장 📰⚠️. 2022년 자체 라벨팀을 감원한 것이 자동화의 뒷면임 📰.
  • ⑤ 학습 클러스터 Cortex(2026년 1분기 "H100 상당 10만 장 이상", Cortex 2 추가) 📰⚠️ (TechCrunch). v14.3 릴리스 노트에 "강화학습 단계"가 등장 📰⚠️.
  • ⑥ 시뮬레이터는 비공개. 2026년 보도는 "실도로 데이터 → 자동 라벨링 → 신경망 시뮬레이터 → 강화학습 → 새 모델 → 플릿 검증"의 루프를 전함 📰⚠️ (Not a Tesla App).
  • ⑦⑧ 여러 라운드 섀도 후 활성화 → 플릿 0.1% 미만 → 약 10% → 광역. 대형 버전 약 10개월(v13 → v14), 포인트 릴리스 1~2주 📰⚠️.
  • 구조의 특징
  • 플릿이 ①·②·⑦을 동시에 맡음. 같은 양산차가 데이터 수집기이자 섀도 검증 장치이자 단계적 배포 대상임. 로보택시형과 가장 다른 점임.
  • 라이다가 없으므로 정답(④)을 카메라 다중 주행 재구성으로 만들어야 함. 자동 라벨링에 GPU 4,000장을 따로 둔 이유임(2022) 📰⚠️.
  • 데이터 주권이 플라이휠을 둘로 쪼갬. 중국 도로 데이터를 미국으로 못 보내 상하이 데이터센터와 중국 내 학습 인프라를 따로 두었고, 중국 당국의 데이터 안전 검사를 외자 기업 최초로 통과함 📰 (Electrek 2026-02, 이투데이).
  • 약점: 충돌 집계 방식이 정부 데이터와 달라 안전 통계의 독립 검증이 없음 📰⚠️. 데이터·시뮬레이터·모델 모두 비공개라 외부가 검증할 수 없음.

4.3 Waymo — 하나의 파운데이션 모델이 운전자·시뮬레이터·평가자를 겸한다

  • 플라이휠이 도는 순서
  • ①② 로보택시 플릿(2026년 3월 무인 누적 2억 2,060만 마일, 주 400만 마일 이상)이 카메라·라이다·레이더 로그를 만듦 📰 (Waymo).
  • ③ "ML Factory" 슬라이드(그림 9): 센서 로그 → 데이터 마이닝·능동학습으로 선별 📰.
  • ④ 라이다 시퀀스 전체를 쓰는 3D 자동 라벨링(CVPR 2021)이 사람 라벨과 대등 📰; 초기의 사람 라벨링에서 자동 라벨링으로 이동했다고 밝힘 📰 (Scale 블로그).
  • ⑤ Waymo Foundation Model(Gemini 계열 기반)을 크기 제한 없는 "교사"로 학습시키고, 차에 실을 "학생" 모델로 증류함 📰 (Waymo 블로그 2025-12).
  • ⑥ 같은 파운데이션 모델이 시뮬레이터(Genie 3 기반 Waymo World Model, 카메라·라이다 동시 생성)와 평가자(Critic)의 바탕이 됨 📰. Carcraft는 하루 800만~1,000만 마일, 새 소프트웨어마다 전체 시나리오를 재실행하고 사고 시나리오는 fuzzing 📰.
  • ⑦⑧ 테스트 트랙 + 실도로 → 도시 단위 롤아웃. 플릿 통계를 안전 허브와 동료 심사 논문으로 공개(중상·사망 충돌 94% 감소 등) 📰.
  • 구조의 특징
  • "운전자·시뮬레이터·평가자가 같은 모델"이라는 설계. 한 모델이 좋아지면 세 단계(⑤⑥⑧의 평가)가 함께 좋아지는 구조로, 이를 "지속적 선순환(flywheel)"이라고 스스로 부름 📰.
  • 플릿은 작지만 센서 밀도가 높음. 라이다가 있어 3D 정답을 만들기 쉽고, 그 대신 플릿 규모(Tesla의 1/60 수준)를 시뮬레이션(실주행 2,000만 vs 시뮬 200억 마일)으로 보충함 📰.
  • 공개도가 가장 높음. Waymo Open Dataset·WOD-E2E(롱테일 데이터셋)·안전 케이스 백서·안전 허브 📰. 2026년 8월에는 한국에서 모은 사고·사건 장면을 가명 처리해 국외로 가져가는 절차를 개인정보위에 문의함 📰 (머니투데이 2026-08).

4.4 현대차그룹 — 42dot·모비스·NVIDIA·Motional의 분업으로 도는 두 개의 트랙

  • 발표 내용(2026-09-11 미디어데이, 9-13 보도) 📰 (현대차그룹, 오토일렉트로닉스, 네이트 뉴스): "차량에서 실제 주행 데이터를 확보하고 이를 AI 모델 학습과 검증에 활용한 뒤, 개선된 AI 모델을 다시 차량에 적용해 새로운 데이터를 확보하는 선순환 구조"를 자율주행 전략의 핵심 엔진으로 선언함.
  • 플라이휠이 도는 순서(공개된 범위)
  • ① Hard Example Mining: AI 모델이 오인식하거나 판단하기 어려워하는 주행 상황(엣지 케이스)을 자동으로 선별해 우선 학습에 씀 📰. 3.1절의 "모델 점수 트리거"에 해당함.
  • ② 데이터 원천은 세 겹임. (a) 42dot의 종단간 시스템 Atria AI를 실은 SDV 테스트 차량(2026년 9월 서울 도심 비보호 좌회전 등 무개입 주행 시연) 📰 (한국경제TV) (b) 2026년 말부터 국내 양산차에 Atria AI를 실어 엣지 케이스 수집, 국토부와 협력해 전남·광주에 "SDV Pace Car" 투입 📰 (c) 장기적으로 190여 개국 연 700만 대 판매망을 데이터 확보 기반으로 삼겠다는 계획 📰 (지피코리아).
  • ⑤ Continuous Training 파이프라인: 실제 차량 평가에서 발견된 취약점을 새 학습 데이터로 반영해 모델을 반복 개선 📰.
  • ⑥ 실제 주행 데이터를 3차원 환경으로 재구성해 위험하거나 반복하기 어려운 상황을 가상으로 재현하고 검증 📰(3.3절의 "재구성" 갈래). 현대모비스는 실차 센서 데이터를 시뮬레이터에 통합한 검증 체계를 발표하고, 시뮬레이터 60대 연결 시 "1만 시간 검증을 1주일에"를 목표로 함(계획) 📰⚠️ (PR Newswire).
  • ⑧ 이중 트랙: NVIDIA DRIVE AGX Thor·Hyperion 기반 L2+/L2++ 양산 2028년 상반기, 자체 Atria AI 기반 L2++ 양산 2029년 하반기 📰. L4는 Motional을 통해 진행 📰(2026-03 GTC 발표).
  • 구조의 특징
  • 단계별로 담당 주체가 다른 "그룹 내 분업"임. 42dot = 모델(Atria AI)과 선별(Hard Example Mining), 현대모비스 = 센서·HIL 검증, NVIDIA = 양산 플랫폼과 검증 도구, Motional = 로보택시 데이터의 별도 루프. Tesla처럼 한 조직이 9단계를 쥔 구조가 아님.
  • 플라이휠이 두 개 병렬로 돎. NVIDIA 트랙(2028)과 Atria 트랙(2029)이 각각 양산됨. 두 트랙의 데이터가 한 저장소로 합쳐지는지, 라벨링(④)·검색 도구(③)를 자체로 하는지 외부 도구인지는 공개 자료에 없음 ⚠️.
  • 출발 시점의 차이. 현재 수집 차량은 테스트 차량 위주이고 양산차 탑재는 2026년 말부터임. 4.1절 표의 플릿형(Tesla·XPeng·Momenta)에 비해 ①②가 늦게 시작되며, 700만 대 판매망은 "잠재력"이지 아직 플릿이 아님. 대신 국내 원본 영상 학습은 규제 샌드박스 승인에 묶여 있어(5.5절) 수집 자체가 제도 조건임.
  • 비교 대상: Toyota·Woven Arene은 동의 기반 주행 데이터 수집(Arene Data)과 가상 검증(Arene Tools)을 2025년 RAV4부터 적용 📰; VW는 Bosch와의 얼라이언스에 약 15억 유로를 쓴 뒤 2026년 7월 조기 종료해 OEM 자체 구축의 실패 비용을 보여 줌 📰 (electrive).

4.5 Momenta·Mobileye·Wayve — 남의 차에서 데이터를 받는 세 가지 방식

  • Momenta — OEM 양산차에서 공급자로 돌아오는 플라이휠
  • ①② 데이터 원천은 24개 OEM(BMW 중국·아우디·도요타·BYD·포드 등)의 양산차 100만 대 이상 📰 (Momenta). 상장 서류는 "양산차가 실도로 데이터를 모으고 → 알고리즘이 좋아지고 → 더 많은 양산차에 실리고 → 더 많은 데이터가 생기는" 폐루프를 사업 모델로 명시함 📰 (Longbridge).
  • ⑤ R6 "플라이휠 대형 모델"은 고가치 클립 7,000만 개와 실주행 30억 km로 학습한 강화학습 기반 종단간 모델(2025-08 Buick Electra L7 첫 탑재) 📰 (Momenta R6); R7(2026-04)은 사전학습·시뮬레이션·강화학습 3층 구조, 누적 120억 km와 "골든 데이터" 1억 건 📰.
  • ⑦⑧ 실차 검증과 배포는 OEM 프로그램 단위(세대 연 1회)로, Momenta가 직접 OTA를 쥐지 않음 📰.
  • 특징: 플라이휠의 주인은 공급자, 플릿의 주인은 OEM. 어떤 데이터가 얼마나 OEM에서 Momenta로 돌아오는지(계약 조건)는 비공개 ⚠️. Mercedes 중국 CLA·BMW 중국 iX3처럼 "중국 안에서만" 돌아오는 지역 한정 회수가 많음 📰.

4.8 회사들을 가로지르는 공통점과 갈림길

  • 공통점 ① 모두가 직접 쥐는 단계는 ①·⑤·⑧임. 온보드 선별(무엇을 올릴지), 학습(모델 자체), 배포 책임(규제·안전 케이스)은 어느 회사도 외부에 맡기지 않음. 반대로 ③④⑥(검색·라벨링·시뮬 도구)은 사거나 열어 씀. 차별화와 법적 책임이 있는 자리만 안에 두는 셈임.
  • 공통점 ② 라벨링(④)은 "사람 외주"에서 "자동 라벨링 + 사람 검수"로 옮겨감. Tesla 라벨팀 감원(2022), Waymo의 자동 라벨링 전환, NVIDIA·Bosch의 자동 라벨링 도구, Scale AI의 자율주행 비중 축소가 같은 흐름의 앞뒤임 📰.
  • 공통점 ③ 시뮬레이션(⑥)이 월드모델로 바뀌고, 그 안에서 학습(⑤)까지 하려 함. Waymo World Model(2026-02), Wayve GAIA-4(2026-08), XPeng X-World, Momenta R7, comma 학습된 시뮬레이터(2026-03), NVIDIA Cosmos·AlpaGym 📰🔍. 2026년 한 해에 거의 모든 진영이 "생성 모델로 시험한다"를 선언했고, Waymo·Wayve·comma는 학습과 검증을 같은 월드모델로 함.
  • 갈림길 ① 데이터가 누구 차에서 생기나. (a) 자기 양산차(Tesla·XPeng·comma·현대차 계획): 양이 많고 섀도 검증이 공짜지만 센서가 얇음(카메라 위주). (b) 자기 로보택시(Waymo·Baidu): 센서가 두껍고 3D 정답이 쉽지만 양이 적어 시뮬 비중이 큼. 이 선택이 ④ 라벨 방식(카메라 재구성 vs 라이다)과 ⑥ 시뮬 비중을 결정함.
  • 갈림길 ② 데이터가 누구에게 돌아가나(회수권). OEM 자체 회수(Tesla·XPeng·현대차) / 공급자로 회수(Momenta·Mobileye) / 지역별로 갈라진 회수(Mercedes CLA: 중국 Momenta·미국 NVIDIA, BMW iX3: 중국 Momenta·글로벌 Qualcomm) 📰. 공급자형은 OEM과의 계약이 곧 플라이휠의 연료이고, 데이터 주권 규제는 회수 경로를 국경 안으로 자름(Tesla 상하이, 중국 한정 Momenta 회수).
  • 갈림길 ③ 플라이휠의 산출물이 무엇인가. 모델(대부분) / 지도(Mobileye REM) / 검증용 월드모델·도구(Wayve GAIA-3, NVIDIA) / 데이터셋(Waymo WOD-E2E, NVIDIA 1,700시간). 산출물이 다르면 올리는 데이터도 다름 — Mobileye는 원본 영상을 아예 올리지 않음.
  • 갈림길 ④ 한 조직이 도느냐, 분업으로 도느냐. Tesla·XPeng은 한 조직이 9단계를 쥐고, 현대차그룹은 42dot·모비스·NVIDIA·Motional의 분업에 두 트랙이 병렬임. 분업은 각 단계의 전문성을 사 올 수 있지만, 단계 사이의 데이터 이동(누구 저장소에, 어떤 형식으로)이 병목이 될 수 있음(⚠️ 추정, 5.4절의 반출 비용 참조).
  • 관찰: 플릿 규모와 배포 주기가 함께 움직임. Tesla 포인트 릴리스 1~2주(140억 마일), comma 약 2개월(3억 마일), Momenta 세대 연 1회(OEM 프로그램), 현대차 2028·2029(플릿 형성 전) 📰. 플릿이 크면 섀도 검증이 빨리 끝나 배포를 자주 할 수 있다는 해석이 가능하나, 조직·규제 요인도 섞여 있어 인과로 단정할 수는 없음 ⚠️.
시사점

회사를 "유형"으로 나누는 것보다 "9단계 중 어디를 쥐고, 데이터가 누구 차에서 생겨 누구에게 돌아가는가"로 보는 편이 차이를 잘 드러냄. 이 기준으로 보면 후발 주자의 선택지는 셋임. 플릿을 빨리 키우거나(양산차 탑재), 센서를 두껍게 하고 시뮬로 보충하거나(로보택시형), 공급자의 플라이휠에 플릿을 빌려주고 모델을 받거나(Momenta형).

5. 데이터 플라이휠의 진화, 병목과 해법, 향후 진화 방향

개요

플라이휠이 2021년의 "데이터 엔진"에서 2026년의 플라이휠로 어떻게 바뀌었는지를 먼저 놓고(5.1), 지금 플라이휠이 막히는 네 곳(데이터 발견·검증·비용·규제)을 정의 → 원인 → 해법과 비용 → 기업 사례 순서로 분석함(5.2~5.5). 마지막으로 다음 5년의 진화 방향을 병목별 해법, 기술 성숙도, 차량 HPC 플랫폼 관점에서 정리함(5.6).

핵심 결론
  1. ①2021년과 2026년의 플라이휠은 단계는 같고 부품이 바뀜. 사람이 짠 트리거 → 임베딩 검색, 사람 라벨링 → 파운데이션 모델 자동 라벨링, 로그 재생 → 3D 재구성과 생성형 월드모델, 모방학습 → 폐루프 강화학습, 연 단위 릴리스 → 주 단위 OTA.
  2. ②병목은 네 곳이며 각각 해법이 있지만 완전한 해법은 없음. 데이터 발견(검색·생성으로도 "모르는 것을 모르는" 영역은 못 잡음), 검증(시뮬레이터 자체를 검증해야 함), 비용(온보드 선별 → 자동 라벨링 → 현지 학습 순), 규제(수집·배포·기록 세 단계를 직접 건드림).
  3. ③향후 방향은 월드모델 기반 검증의 규제 증거화, 학습된 시뮬레이터 안에서의 학습, 국경 안 데이터 공유, 에이전트형 개발, 파운데이션 모델 라벨링, "증거로서의 로깅"이고, 이 중 온보드에 걸리는 것이 차량 HPC 플랫폼의 설계 조건이 됨.

5.1 데이터 플라이휠의 진화 — 2021년 데이터 엔진에서 2026년 플라이휠로

  • 세 시기로 나누면
  • 2010년대 후반 — 데이터셋 한 번, 학습 한 번: 사람이 규칙을 쓰고, 학습 모델은 인지 일부에만 쓰였으며, 데이터셋은 한 번 모아 사람이 라벨링해 학습함. 1.3절의 네 가지 한계(롱테일·분포 변화·성능 회귀·검증 한계)가 여기서 드러남(이 시기 구분은 이 보고서의 요약이며 별도 출처 없음 ⚠️).
  • 2021년 전후 — 데이터 엔진: 루프가 생김. 사람이 조건을 코드로 쓴 트리거가 차에서 돌고, 걸린 클립을 올려 오프라인에서 자동 라벨링하고, 재학습해 섀도 모드로 배포함.
  • 2025~2026년 — 플라이휠: 루프의 모양은 같지만 각 단계의 부품이 큰 모델과 클라우드 시뮬레이션으로 바뀜.
  • 2021년 전후의 교과서 = Tesla AI Day 데이터 엔진 📰 (CleanTechnica, Electrek).
  • 흐름: 사람이 쓴 트리거가 차에서 돎(①) → 걸리면 약 10초 클립 업로드(②) → 오프라인 자동 라벨링(④) → 재학습(⑤) → 섀도 모드로 배포(⑦⑧).
  • 당시 수치: 누적 100만 클립, 60억 개 객체 라벨, 1.5PB, 주당 1만 클립 자동 라벨링.
  • 2026년 플라이휠 — 단계는 같고 부품이 바뀜: 아래 표의 "단계" 열은 2.2절의 번호(①~⑨)이고, 각 행은 그 단계에서 쓰는 부품이 어떻게 바뀌었는지임.
2.2절 단계 무엇을 하는 일인가 2021년 전후 2025~2026년 무엇이 달라졌나
①③ 고칠 상황 찾기 플릿이 겪은 수백만 장면 중 모델이 틀린 상황과 그 비슷한 장면을 찾아내는 일 사람이 조건을 코드로 쓴 트리거(Tesla 221개)로 차 안에서 걸러 냄 📰 임베딩 검색: 영상마다 내용을 요약한 숫자 목록(임베딩)을 붙여 두면 뜻이 비슷한 영상은 숫자도 비슷해짐. "비 오는 밤 공사 구간" 같은 글을 같은 방식으로 숫자로 바꿔 가까운 영상을 찾음. NVIDIA Cosmos Dataset Search는 약 800만 영상으로 학습한 영상-텍스트 임베딩 모델(Cosmos-Embed1)을 씀 📰; Voxel51 FiftyOne 📰 무엇을 찾을지 미리 코드로 정해 두지 않아도 되고, 트리거에 안 걸린 장면도 나중에 찾을 수 있음
④ 라벨링 영상에 정답(물체 위치·차선·궤적)을 붙이는 일 사람 라벨링 회사(Scale AI, 인력 24만 명) 📰; Tesla는 2022년 자체 라벨팀 감원 📰 파운데이션 모델 자동 라벨링: NVIDIA Cosmos Curator가 "처리·주석·필터·중복 제거"를 맡고 🔍 (Cosmos README), Cosmos Reason 같은 시각언어모델이 "왜 이렇게 운전했나"까지 글로 붙임 📰 라벨 비용이 사람 수가 아니라 GPU 시간에 비례
⑥ 장면 재현 기록된 상황을 다시 돌려 새 모델을 시험하는 일 로그 재생 + HIL(dSPACE 리플레이 시스템) 📰 3D 재구성: Waymo Block-NeRF는 사진 280만 장으로 샌프란시스코 한 구역(0.5km²)을 35개 신경 모델로 재구성 📰 (arXiv 2202.05263); NVIDIA NuRec은 3D 가우시안 스플래팅으로 주행 로그를 다시 걸어 다닐 수 있는 3D 장면으로 만듦 📰 기록된 그대로만이 아니라 "그때 왼쪽으로 꺾었다면"을 볼 수 있음
⑤⑥ 장면 생성 겪어 본 적 없는 상황을 만들어 학습·시험에 쓰는 일 사람이 시나리오 파일(OpenSCENARIO)을 작성 📰 생성형 월드모델: Wayve GAIA-3(150억 파라미터, 10배 데이터) 📰 (Wayve); Waymo World Model(Genie 3 기반) 📰; NVIDIA Cosmos 📰 본 적 없는 상황을 영상으로 만들어 냄
⑤ 학습 모델을 고치는 일 기록된 주행을 흉내 내는 모방학습(개루프) 폐루프 강화학습·학습된 시뮬레이터: NVIDIA AlpaGym은 시뮬레이터 안에서 정책이 스스로 운전하며 배움 📰; openpilot 0.11은 "학습된 시뮬레이터로 전량 학습" 🔍 모델이 자기 실수의 결과를 겪으며 배움
⑥ 평가 새 모델이 좋아졌는지 재는 일 기록 궤적과의 거리(ADE/FDE 같은 규칙 지표) 사람 선호 지표: Waymo WOD-E2E의 RFS 📰; LLM-as-judge(일반 플라이휠) 🔍 "기록과 같은가"에서 "사람이 보기에 좋은가"로
⑧ 배포 새 모델을 차에 내보내는 일 연 단위 대형 릴리스(Tesla v13 → v14까지 약 1년) 📰 주 단위 OTA(v14.x는 1~2주 간격) 📰 (보도) 루프 한 바퀴가 짧아짐
  • 바뀐 부품들의 공통점: 사람이 하던 일(트리거 작성, 라벨링, 시나리오 작성)을 큰 모델이 대신하고, 실차로만 하던 일(재현, 검증)을 클라우드가 대신함.
  • 그래서 병목이 옮겨감: 한 바퀴의 병목이 "사람 손"에서 "GPU와 데이터 파이프라인, 그리고 시뮬레이션을 얼마나 믿을 수 있는가"로 이동함. 다음 절부터 그 병목을 하나씩 봄.
시사점

플라이휠을 평가하는 잣대는 세 변수로 요약됨 — 한 바퀴를 얼마나 자주(주기), 얼마나 싸게(바퀴당 비용), 얼마나 믿을 수 있게(검증 신뢰도) 돌리느냐. 5.2~5.5의 네 병목은 이 세 변수 중 하나 이상을 막는 곳이고, 각 해법도 이 세 변수로 평가하면 됨.

5.2 병목 ① 데이터 발견 — 무엇이 필요한지 모른다

  • 정의: 가장 어려운 데이터는 "아직 본 적 없어서 찾을 줄도 모르는" 데이터임. ISO 21448(SOTIF)은 이를 "모르는 불안전 시나리오(영역 3)"라 부르고, 이 영역을 합리적 노력으로 최대한 줄이는 것을 표준의 핵심으로 둠 📰 (TÜV SÜD 백서).
  • 왜 생기나
  • 희소성: Waymo는 수억 마일 플릿에서 발생 빈도 0.03% 미만 상황을 골랐는데 12시간 분량이었음 📰. 플릿이 아무리 커도 드문 조합은 몇 번 안 나옴.
  • 트리거의 한계: 트리거는 "미리 정한 조건"이므로, 정하지 않은 상황은 걸리지 않음. 불확실성 기반 능동학습도 초기 라벨 집합에 아예 없는 클래스("unknown unknown")를 잡지 못함 📰 (해설).
  • 해법과 비용
해법 무엇을 겨냥하나 비용·조건 한계
임베딩·자연어 검색(3.2절) "알지만 못 찾은" 장면 — 트리거에 안 걸렸지만 비슷한 장면 플릿 영상 전체를 임베딩해 두는 GPU 비용(Cosmos Curator 기준 2,000만 시간에 Blackwell 14일 📰) 검색어를 아는 상황만 찾음
모델 불일치·섀도 트리거(3.1절) 현행 모델과 후보 모델(또는 앙상블)이 갈리는 순간 온보드에 후보 모델을 같이 돌릴 추론 여유 두 모델이 같이 틀리면 못 잡음
생성형 월드모델(3.3절) "본 적 없는" 조합 — 플릿이 못 본 상황을 만들어 시험 월드모델 학습·추론 비용, 만든 장면의 현실성 검증(5.3절) 무엇을 만들지는 여전히 사람이 정함
월드모델의 "놀람" 신호(연구) "무엇을 모르는지 모르는" 영역 — 예측 월드모델이 다음 장면을 못 맞히는 순간을 희소 사건으로 봄 온보드 또는 오프라인에서 예측 모델을 계속 돌려야 함 2026년 연구 단계 📰 (arXiv 2608.29772)
  • 기업 사례
기업 어떻게 푸나 근거
Tesla 트리거 221개 + 섀도 모드 + 틀린 사례를 단위 테스트로 남기고 비슷한 사례를 플릿에서 회수(boost) 📰
NVIDIA 모델 앙상블의 불일치로 고른 데이터가 수동 선별보다 야간 보행자 3배·자전거 4.4배 개선(연구); Cosmos Dataset Search로 글 검색 📰🔍

Voxel51 페타바이트급 플릿 로그에서 임베딩·자연어 검색으로 엣지 케이스를 캐는 도구 📰
시사점

검색은 "알지만 못 찾은" 데이터를, 생성은 "본 적 없는" 데이터를 겨냥함. 둘 다 "무엇을 모르는지 모르는" 영역은 못 잡으므로, 월드모델의 놀람 신호 같은 발견 기법이 다음 과제임. 온보드에서 후보 모델을 같이 돌리는 섀도·불일치 트리거는 차량 HPC 자원에 걸림(5.6절).

5.3 병목 ② 검증 — 시뮬레이션을 얼마나 믿을 수 있나

  • 정의: 시뮬레이션이 검증의 주 수단이 됐지만(2.3절 차이 5), 시뮬레이션에서 좋은 점수가 도로에서의 안전으로 이어진다는 보장이 없음. 시뮬레이터 자체를 검증해야 하는 문제임.
  • 왜 생기나
  • 개루프 점수의 허약함: nuScenes 개루프 평가에서 카메라·라이다 없이 과거 궤적만 외삽해도 최신 모델을 이기는 사례가 보고됨 📰. 정적 데이터셋 점수가 도로 안전과 다른 것을 재고 있다는 뜻임.
  • 시뮬–실제 격차: 재구성·생성 장면은 기록 범위 밖에서 품질이 떨어지고, 생성 장면은 물리적으로 그럴듯한지 따로 확인해야 함(3.3절).
  • 배포 교란: Bench2Drive-Robust(2026-05)는 프레임 드롭·GPS 잡음·추론 지연 같은 "배포 교란"이 폐루프 성능을 크게 떨어뜨리는데 기존 이미지 손상 평가로는 잡히지 않는다고 보고함 📰 (arXiv 2605.18059).
  • 해법과 비용
해법 내용 비용·조건 근거
검증 사다리(3.4절) 개루프 → 유사 폐루프 → 사람 선호 → 시뮬 폐루프 → 회귀 세트 → HIL → 섀도 → 단계적 OTA. 각 단이 이전 단이 못 보던 것을 봄 단이 늘수록 한 바퀴가 길어짐. 어느 단을 생략할지가 설계 문제 🔍📰
의사 시뮬레이션 NAVSIM v2는 3D 가우시안 스플래팅으로 후속 관측을 합성해 폐루프 시뮬과 상관 0.89를 얻으면서 환경 상호작용을 6배 줄임 폐루프 시뮬보다 싸지만 상관 0.89는 "같다"가 아님 📰🔍 (NAVSIM)

5.6.3 차량 HPC 플랫폼 관점 — 온보드가 준비해야 할 것

  • 전제: 9단계 중 ①②⑦⑧⑨는 차 안에서 돎. 위 방향 가운데 온보드에 걸리는 것을 이 보고서의 근거에서 추리면, 지금 필요한 다섯 가지와 앞으로 더해질 세 가지임.
# 요구 왜 필요한가 근거
1 섀도 실행 자원 현행 모델과 후보 모델을 동시에 돌려야 불일치 트리거(5.2절)와 섀도 검증(5.3절)이 됨 Tesla 섀도 모드 📰
2 선별·압축·두 단계 로깅 요약 로그 + 저화질 영상 + 원본 지목 업로드는 저장·통신 예산과 온보드 인코더를 전제로 함(5.4절) openpilot 🔍
3 규제 기록의 무결성 DSSAD·EDR·R156 버전 식별·이력은 변조 방지 저장과 시간 동기화를 요구함(5.5절) 📰
4 HIL 재생 호환 원시 센서·버스 데이터를 실제 ECU에 시간 맞춰 주입하려면 플랫폼의 입력 경로가 재생을 지원해야 함(5.3절) dSPACE, 현대모비스 📰
5 OTA 관리 프로세스 R156의 SUMS·RxSWIN 요건은 업데이트 경로의 설계 조건임(5.5절) 📰
6 (앞으로) 온디바이스 큐레이션 연산 임베딩·소형 VLM을 차 안에서 돌려 드문 장면을 차 안에서 고르면 업로드 비용이 더 줄지만, 추론 자원이 더 듦 ⚠️ 추정(5.6.2)
7 (앞으로) 교사-학생 증류 모델의 실행과 안전 감시 학습된 시뮬레이터 안에서 배운 학생 모델이 실차에 실리면, 시뮬–실제 격차를 런타임에서 감시하는 모니터가 필요함 Waymo 교사-학생 📰, comma 0.11 🔍, ⚠️ 추정
8 (앞으로) 지역별 모델·데이터 변형 관리 데이터 주권으로 지역마다 다른 모델·로깅 정책이 실리면, 같은 플랫폼에서 변형을 식별·관리해야 함 Tesla 상하이, Mercedes CLA 분할 📰, ⚠️ 추정
시사점

플라이휠은 클라우드만의 일이 아님. 첫 단계(선별·섀도)와 마지막 단계(OTA·규제 기록)는 차 안에 있고, 향후 방향(온디바이스 큐레이션·증류 모델·지역별 변형)은 온보드 요구를 더 늘림. 차량 HPC 플랫폼이 이 여덟 가지를 지원하지 않으면 플라이휠의 시작과 끝이 막힘.

부록 A. 용어 풀이

용어 뜻
데이터 플라이휠 서비스를 쓰면서 나온 데이터로 모델을 고치고, 고친 모델이 더 좋은 데이터를 만드는 반복 구조. 자율주행에서는 "데이터 엔진", "폐쇄루프"라고도 부름
종단간(end-to-end, E2E) 카메라 영상이 들어가면 조향·제동이 바로 나오는 하나의 학습 모델. 중간에 사람이 짠 규칙이 없음
롱테일(long tail) 각각은 드물지만 종류가 무한히 많은 예외 상황. 빈도 그래프의 긴 꼬리
분포 변화(distribution shift) 학습할 때 본 상황의 분포와 실제로 만나는 상황의 분포가 다른 것. 도시·날씨·나라가 바뀌면 생김
파국적 망각(catastrophic forgetting) 새 데이터로 다시 학습한 모델이 예전에 잘하던 것을 잊는 현상
트리거(trigger) 차 안에서 "이 순간의 데이터를 저장·업로드하라"고 판단하는 조건. 규칙, 모델 점수, 사람 버튼이 있음
섀도 모드(shadow mode) 새 모델을 차에 싣되 제어권은 주지 않고, 그 판단을 기록해 현행 모델·운전자와 비교하는 방식
자동 라벨링(auto-labeling) 클라우드의 큰 모델이 미래 프레임과 여러 주행을 합쳐 정답(박스·차선·궤적)을 만드는 것
임베딩(embedding) / 임베딩 검색 영상이나 글의 내용을 요약한 숫자 목록. 뜻이 비슷하면 숫자도 비슷하게 나오도록 학습해 두므로, 글로 검색어를 넣어 숫자가 가까운 영상을 찾을 수 있음
Hard Example Mining 모델이 틀리거나 판단을 어려워한 상황을 자동으로 골라 우선 학습에 쓰는 기법. 현대차그룹이 플라이휠의 선별 기술로 명시함
교사-학생 증류(distillation) 크기 제한 없는 큰 모델(교사)을 먼저 학습시키고, 차에 실을 작은 모델(학생)이 그 출력을 따라 배우게 하는 방법
SUMS / UN R156 소프트웨어 업데이트 관리체계. 제조사가 업데이트 관리 체계를 인증받고, 버전마다 식별 번호(RxSWIN)를 붙이며, 호환성 확인·안전 설치·기록을 요구하는 UN 규정
재생 / 재구성 / 생성 합성 데이터의 세 갈래. 기록을 그대로 틀기 / 기록을 3D로 복원해 다른 시점에서 보기 / 조건을 주고 없던 영상을 만들기
3D 가우시안 스플래팅(3DGS) 장면을 수백만 개의 작은 타원체(가우시안)로 표현해 빠르게 다시 그리는 3D 재구성 기법
월드모델(world model) 지금 장면과 행동을 주면 다음 장면을 예측·생성하는 모델. 시뮬레이터로 쓰임
개루프 / 폐루프 평가 기록 궤적과의 거리만 재기 / 시뮬레이터 안에서 실제로 운전시켜 결과를 재기
PDMS / RFS NAVSIM의 유사 폐루프 점수 / Waymo의 사람 평가자 선호 점수
HIL(Hardware-in-the-Loop) 실제 제어기(ECU)에 기록·합성 센서 데이터를 주입해 시험하는 방법
OTA(Over-the-Air) 무선으로 차량 소프트웨어를 갱신하는 것. UN R156이 관리 방식을 규정함
DSSAD / EDR 자율주행 시스템의 켜짐·꺼짐·개입을 기록하는 장치 / 사고 순간 데이터를 기록하는 장치
SOTIF(ISO 21448) 고장이 없어도 기능의 한계 때문에 생기는 위험을 다루는 안전 표준
RxSWIN UN R156이 요구하는 형식승인 관련 소프트웨어 식별 번호
