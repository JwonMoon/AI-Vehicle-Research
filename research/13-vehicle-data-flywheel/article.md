# 차가 데이터를 모으고, 데이터가 차를 고친다 — 자율주행 데이터 플라이휠의 구조와 기술

**학습 모델이 된 주행 소프트웨어, 왜 "한 바퀴"가 경쟁력이 됐나**

> 2026-10-08 · 사내 리서치 보고서 「자율주행 데이터 플라이휠」(2026-09-22, 2판 2026-09-30) 요약 기사

## 배경 — 모델은 데이터로만 고칠 수 있다

데이터 플라이휠은 운행 중 생긴 데이터로 모델을 고치고, 고친 모델이 더 가치 있는 데이터를 만드는 반복 구조다. 주행 소프트웨어가 학습 모델이 되면서(Tesla FSD v12는 C++ 30만 줄을 신경망 하나로 대체) 모델은 데이터로만 고칠 수 있게 됐다. 드문 상황(롱테일), 지역·날씨 변화, 재학습 뒤의 성능 회귀, 주행 거리로는 안전을 증명할 수 없다는 한계(RAND: "20% 더 안전" 입증에 110억 마일)는 한 번 학습으로는 풀리지 않는다.

## 구조 — 아홉 단계, 그중 네 개는 관문

차량 플라이휠은 차 안 선별 → 업로드 → 검색 → 라벨링 → 학습 → 시뮬레이션 검증 → 실차 검증 → 안전 관문·OTA → 반복의 아홉 단계로 돈다. 챗봇 같은 LLM 서비스와 뼈대는 같지만, 데이터가 차 안 센서에서 생겨 전량 업로드가 불가능하고, 정답이 운전자 개입·사고 같은 물리적 결과이며, 배포가 UN R156 인증 대상이다. 차량에만 있는 네 단계는 모두 통과해야 할 관문이다.

## 작동 방식 — 사람이 하던 일을 큰 모델이, 실차로 하던 일을 클라우드가

공사 구간 작업자를 늦게 인식해 운전자가 개입한 순간을 예로 들면, 차 안에서는 개입 같은 조건에 걸리면 앞뒤 몇 초를 보관하는 트리거, 후보 모델을 제어권 없이 함께 돌려 판단 차이를 기록하는 섀도 모드, 요약본을 먼저 올리고 서버가 지목한 구간만 원본을 올리는 두 단계 업로드가 쓰인다.

클라우드는 영상의 의미를 숫자로 바꾼 임베딩 검색으로 플릿에서 비슷한 장면 수백 개를 회수하고, 자동 라벨링이 미래 프레임과 여러 차량의 주행을 합쳐 3초 뒤 명확히 보인 작업자를 첫 프레임부터 거슬러 표시한다. Waymo는 이런 3D 라벨이 사람 라벨과 동등하다고 보고했고, Tesla는 수작업 500만 시간이 클러스터 12시간으로 줄었다고 주장했다. 사람은 드문 물체만 검수한다.

학습에는 재생(기록 그대로), 재구성(3D 복원 뒤 시점·궤적 변경), 생성(월드모델로 없던 장면 생성)의 합성 데이터가 더해지며, 뒤로 갈수록 없던 상황을 만들 수 있지만 현실과의 격차를 검증해야 한다. 시뮬레이터 안에서 직접 운전하며 배우는 폐루프 강화학습과 교사 모델을 차량용 학생 모델로 압축하는 증류가 그 위에 얹힌다. 검증은 개루프 지표 → 폐루프 시뮬레이션 → 사람 선호 → 회귀 세트 → HIL(실제 제어기에 기록 주입) → 섀도 배포 → 단계적 OTA로 범위를 넓히며, 마지막 단계는 규제 절차다.

## 기업 동향 — 플릿과 모델을 누가 쥐는가

기업은 플릿과 모델의 보유 주체에 따라 자사 양산 플릿형(Tesla·XPeng·comma.ai, 현대차그룹은 계획), 자사 로보택시형(Waymo·Baidu), 파트너 플릿 기반 모델 공급형(Momenta·Mobileye·Wayve), 도구·플랫폼 공급형(NVIDIA·Applied Intuition)으로 나뉜다. 차 안 선별·학습·배포 책임은 모두 자체로 쥐고, 검색·라벨링·시뮬 도구는 사거나 열어 쓴다. 2026년의 무게중심은 월드모델(Waymo·Wayve·Momenta·NVIDIA), 데이터 주권 규제(중국 국외 이전 가이드라인, 한국 샌드박스), 그리고 9월 플라이휠 가동을 선언한 현대차그룹(2028·2029년 양산)이다.

## 향후 방향 — 로깅 통합에서 학습된 시뮬레이터로

플라이휠은 데이터 발견·검증·비용·규제 네 곳에서 막힌다. 성숙도 순으로 보면 개발용 트리거와 규제용 기록을 합치는 로깅 통합은 의무이고, 월드모델 검증은 양산에 들어갔으며, 학습된 시뮬레이터 안에서 배운 모델의 배포는 comma.ai가 첫 사례를 냈고, 플릿 간 공유와 에이전트 운영은 주장 단계다. 플라이휠의 시작(선별·섀도)과 끝(OTA·규제 기록)은 차 안에 있다.

## 시사점

- 데이터 플라이휠은 선택이 아니라 학습 기반 자율주행의 전제 조건이다.
- 차량 플라이휠의 과제는 속도가 아니라 안전 인증·규제 관문을 통과하면서 반복을 유지하는 것이다.
- 경쟁력은 한 바퀴를 얼마나 자주·싸게·믿을 수 있게 돌리느냐로 귀결된다.
- 기업 간 차이는 아홉 단계 중 어디를 쥐고, 데이터가 누구 차에서 생겨 누구에게 돌아가는가에서 갈린다.
- 플라이휠의 시작과 끝은 차 안에 있다. 섀도 실행·두 단계 로깅·규제 기록·HIL 재생·OTA 관리가 차량 HPC 플랫폼의 설계 조건이다.
