## 1. 개요

- **무엇**: 모회사(Bosch vs Continental/AUMOVIO)가 치열한 경쟁 관계인 두 차량 소프트웨어 회사가 "왜, 어디서 손을 잡았는가"를 설명하는 자리
- **첫 공동 결과물**: Elektrobit의 안전 인증 리눅스 **EB corbos Linux for Safety Applications** 위에 ETAS의 ADAS 미들웨어 **EDMS**(Vehicle Software Platform Suite ADAS 프로파일)를 올린 **사전 통합 솔루션**
- **다음 마일스톤**: 첫 양산(SOP) 적용 · 2026-10-20 슈투트가르트 ETAS Connections 공동 데모

## 2. 업계 진단 — 왜 지금인가

- **SDV 프로그램의 현실화**: 과도한 기대가 걷히고 "함께 만드는 협업"에 무게가 실림 (Moritz)
- **진행 중인 재설계**: 존(zonal) 아키텍처 전환은 계속 전속력 (Moritz)
- **기술 융합**: 리눅스처럼 다른 산업(IT·로보틱스)에서 검증된 기술을 자동차 안전 영역까지 가져오는 흐름 (Moritz)
- **고객의 요구**: 다른 생태계에서 이미 풀린 문제를 재사용하고 싶고, 그 **기초 작업을 미리 해 둔 파트너**를 찾음 (Subhash)
- **시장 구조**: HPC 도입 7~8년이 지났지만 컴퓨트 소프트웨어 시장은 **여전히 파편화**, 특정 플랫폼으로 통합되지 않음 → 공동 제안의 빈틈 (Subhash)

## 3. 왜 경쟁사와 손잡았나 — 합의점

**① 층이 다른 보완재만 합친다**
- EB의 몫 = **바닥 층**: EB corbos Linux for Safety Applications. ISO 26262 기능 안전을 확보한 리눅스. 기반은 제공하지만 도메인 기능은 없음
- ETAS의 몫 = **미들웨어 층**: EDMS. ADAS 특화 결정적(deterministic) 데이터 처리·고처리량. Bosch와 쌓은 ADAS 도메인 지식
- 일부 분야(기본 SW·HPC 미들웨어)에서는 여전히 경쟁하며, 그 분야는 협업 대상이 아님 (Subhash·Moritz)

**② 같은 오픈소스 철학 — Eclipse S-CORE**
- ETAS가 S-CORE를 시작한 이유: 고객과 "어디서 비용을 나누고 공동 투자할까"를 논의할 때마다 이 레이어가 거론됨 (Subhash)
- 구조: 범용 부분은 S-CORE(오픈소스) 기반 **General Purpose 프로파일**로, ADAS 특화 부분은 **EDMS**라는 별도 상용 제품으로
- "**오픈소스 그린워싱이 아니다**": 공동 기반(핵심·기본 요소)만 공개하고, 그 위에 각사 차별화 요소를 얹어 사업을 함 (Björn)
- **결정적 신호**: Elektrobit이 자발적으로 S-CORE에 참여해 리눅스를 S-CORE 레퍼런스 OS로 만드는 중. "누가 억지로 끌어당긴 게 아니다" (Björn·Moritz)

**③ 고객의 통합·일정 리스크를 없앤다**
- 업계 패턴: 리눅스로 프로토타입 → 양산 직전 "기능 안전 필요" → 독점 OS로 전환 → 큰 리스크·일정 지연 (Isaac)
- 해법: 처음부터 끝까지 안전 인증 리눅스 + 사전 통합된 미들웨어. "함께 동작하는지"는 더 이상 고객의 숙제가 아님 (Isaac)
- ADAS는 맞춤형(bespoke) 솔루션이 넘쳐남 → **표준화·반복 적용 가능·특정 하드웨어 비종속**으로 (Moritz)

**④ 자회사의 자유**
- 모회사는 치열한 경쟁사지만, 두 소프트웨어 회사는 **그룹 밖 시장을 공략할 자유**가 있음. ETAS는 Bosch 경쟁사에도 공급, EB도 마찬가지 (Subhash)

**⑤ 환경과 문화**
- 예산이 극도로 빠듯한 시장. OEM은 "**SOP 이후에도 살아남을 파트너**"를 원함 → 보완 자산을 합친 "연합 전력" (Subhash)
- 교류를 시작해 보니 문화적으로 잘 맞았고, 둘 다 개방형 협업을 믿음 (Moritz·Subhash)
- "협력과 **비독점성**이 새로운 표준" (Björn)

## 4. 고객이 얻는 가치 (Isaac 중심)

- **통합 부담 제거**: 두 회사가 "함께 동작함"을 보증
- **개발 연속성**: 개발자가 아는 리눅스 도구(Docker·컴파일러·gdb) 그대로, 프로토타입부터 SOP까지 단절 없음. SoC 공급사도 리눅스를 기본 제공
- **벤더 종속 회피**: EDMS는 POSIX 기반이라 아래 OS 교체 가능. EB 안전 솔루션은 **어떤 리눅스와도 동작**. 사이버보안 유지보수 조건 등을 보고 리눅스 공급자 선택 가능
- **안전 실증**: 리눅스 기반 기능 안전 실증 사례(proof points) 확보, ISO 26262 평가에 문제 없다고 강조
- **스택 완성**: "OS는 OS일 뿐, 고객이 원하는 건 전체 스택" → EDMS로 스택 완성

## 5. 로드맵

- **출발점**: EDMS + ADAS/AD 사용 사례 (결정적 재연산 등)
- **확장**: S-CORE 기반 플랫폼 제품군과의 추가 통합 → 범용 프로파일로 다른 HPC 도메인(게이트웨이·바디 컴퓨터 등)까지
- **EB 측 확장**: 칩 지원 확대, 콕핏 안전·경고등(telltale) 렌더링 등 다른 기능 도메인, 요구사항이 비슷한 인접 시장
- **시장 반응**: JSAE(도쿄·요코하마) 첫 발표 후 "존재해서는 안 될 파트너십" 헤드라인, 고객 문의 급증
- **다음**: 첫 **SOP** 실증 → 2026-10-20 ETAS Connections(슈투트가르트) 공동 데모

## 6. 5년 뒤 ADAS 플랫폼 전망 (Subhash)

1. **중앙집중형 아키텍처 도입 지연** — 비용 압박으로 OEM은 기존 E/E 아키텍처를 최대한 활용하며 관리된 전환. 빅뱅·그린필드는 예외
2. **ADAS 대중화** — L2·L2++가 대중 시장으로. 이번 솔루션이 이를 뒷받침
3. **지역화** — 기술 선도 지역과 채택 선도 지역이 다르게 전개

## 8. 한 문장 결론

**"경쟁 영역은 그대로 두고, 레이어가 다른 보완 영역에서만 협력하되, 비차별 기반은 오픈소스(S-CORE)로 공유한다."**
— OS/미들웨어 층 분담 + 오픈 코어 철학 + 고객의 통합·SOP 리스크에 대한 공통 진단 + 개방형 협업 문화가 맞물린 결과.
