## 0. 왜 이 조사인가 — 한눈에 보기

**한 문장 질문**: 2026년 11월 현재 AI 에이전트(음성 에이전트 포함)는 *무엇을 얼마나 믿고 맡길 수 있는 수준*이며, 그 기준선(baseline)을 **숫자(정량)** 와 **성숙도(정성)** 로 어떻게 표현할 것인가?

"에이전트"라는 말이 챗봇부터 몇 시간짜리 자율 과업까지 다 가리키기 때문에, 조사의 절반은 **측정 가능한 정의로 쪼개는 일**(1장)이고 나머지 절반은 그 좌표계 위에 공개 벤치마크·제품·오픈소스·자체 측정을 찍는 일(2~5장)이다.

## 1. 용어와 작업 정의 — "에이전트"를 측정 가능하게 쪼개기

### 1.1 작업 정의

이 조사에서 **AI 에이전트**는 "언어 모델(또는 멀티모달 모델)이 목표를 받아 **도구를 호출하고 결과를 관찰하며 여러 단계를 스스로 진행**해 과업을 끝내는 시스템"으로 정의한다. 단발 질의응답(챗봇)은 비교 기준점(L0)으로만 포함한다.
**음성 에이전트**는 "음성 입·출력을 가진 에이전트"로 정의하며, 음성 명령만 받고 정해진 동작만 하는 구형 비서는 L0~L1에 놓인다.

### 1.2 4축 분류 체계 (조사 전체에서 재사용하는 좌표계)

**축 ① 자율성 사다리 (L0~L4)**

| 레벨 | 이름 | 무엇을 하는가 | 대표 측정 지표 |
|---|---|---|---|
| L0 | 단발 질의응답 | 한 번 묻고 한 번 답함. 도구 없음 | 정답률·환각률 |
| L1 | 단일 도구 호출 | 한 번의 함수/API 호출로 끝나는 요청(날씨·타이머·검색) | 함수 호출 정확도(BFCL 류) |
| L2 | 다단계 계획·실행(사람 확인 개입) | 여러 도구를 순서대로 쓰고, 중간에 사용자 확인·되묻기 | τ-bench류 과업 성공률, pass^k |
| L3 | 장기 과업 자율 수행 | 수십~수백 단계, 수십 분~수 시간을 사람 개입 없이 진행(코딩·컴퓨터 사용) | SWE-bench·OSWorld·Terminal-Bench 성공률, 과업당 비용·시간 |
| L4 | 다중 에이전트 협업 | 역할이 나뉜 에이전트들이 조정·위임 | 아직 표준 벤치마크 부족 → 정성 평가 |

**축 ② 모달리티**: 텍스트 / 음성(반이중: 말 끝나면 답함 · 전이중: 듣는 중 말하고 끼어들기 가능) / 멀티모달(화면·카메라·문서)

**축 ③ 배치(deployment)**: 클라우드 API / 하이브리드(쉬운 요청은 로컬, 어려운 요청은 클라우드로 라우팅) / 온디바이스(로컬 PC·엣지 보드·모바일)

**축 ④ 도메인**: 범용 소비자 비서 · 코딩 · 컴퓨터/브라우저 사용 · 기업 업무 자동화(고객 응대·백오피스) · 음성 고객 응대(전화)

### 1.3 에이전트 공통 구성 블록 (정성 평가의 체크리스트)

```
 ┌───────────┐   ┌───────────────┐   ┌────────────┐
 │ 모델(두뇌) │──▶│ 계획·루프      │──▶│ 도구/함수   │──▶ 외부 세계(API·파일·브라우저·기기)
 │ LLM/VLM    │◀──│ (관찰→생각→행동)│◀──│ 호출 계층   │◀──
 └───────────┘   └───────────────┘   └────────────┘
       ▲                 │
       │          ┌──────┴──────┐
 ┌─────┴─────┐    │ 메모리       │   ┌────────────┐   ┌────────────┐
 │ 가드레일   │    │ 단기(문맥)   │   │ 평가 하네스 │   │ 프로토콜    │
 │ 권한·확인  │    │ 장기(저장소) │   │ 벤치·추적   │   │ MCP·A2A 등 │
 └───────────┘    └─────────────┘   └────────────┘   └────────────┘
```

각 블록에 대해 조사 시 "표준화됨 / 사실상 표준 / 난립 / 공백"의 성숙도를 판정한다(2.2, 5.2).

### 1.4 각 좌표에서 "무엇을 재는가" 고정

| 정량 축 | 지표 | 주 출처 유형 |
|---|---|---|
| 능력 | 벤치마크 성공률, 사람 기준선 대비, pass^k(k회 반복 모두 성공 확률) | 🔍 공식 리더보드, 📄 논문 |
| 지연·실시간성 | 첫 토큰 지연, 음성 왕복 지연(발화 끝→첫 음성), 과업 완료 시간 | 🔍 공식 문서(주장), 📄 제3자 측정, 자체 측정 |
| 온디바이스 비용 | 모델 파라미터·양자화 후 메모리, tokens/s, VRAM/RAM, 전력 | 🔍 모델 카드, 💬 커뮤니티 벤치, 자체 측정 |
| 시장·채택 | 가격(토큰 단가·좌석), 사용자·기업 도입률, 투자·매출 | 📰 언론·조사기관, 🔍 공식 가격표 |

## 2. 1부 — AI 에이전트 일반: 현존 수준 조사 설계

### 2.1 능력(정량) — 공개 벤치마크 수집

**조사 대상 벤치마크 후보**(조사 시 리더보드 존재·최신성 확인 후 확정)

| 자율성 | 벤치마크 후보 | 무엇을 재나 | 왜 넣나 |
|---|---|---|---|
| L1 | BFCL(Berkeley Function-Calling Leaderboard) | 함수 호출 정확도(단일·병렬·다중 턴) | 도구 호출의 사실상 표준 |
| L2 | τ-bench / τ²-bench | 정책을 지키며 도구+사용자 대화로 과업 완수, pass^k | "사람 상대 에이전트" 신뢰도 |
| L2~L3 | GAIA | 웹·파일·도구를 써서 답하는 범용 과업 | 사람 기준선이 있음 |
| L2~L3 | AgentBench, Humanity's Last Exam(에이전트 설정) | 다환경 범용 | 추세 비교용 |
| L3 | OSWorld(-Verified), WebArena, AndroidWorld, BrowseComp | 컴퓨터·웹·모바일 화면 조작 | 컴퓨터 사용 에이전트 수준 |
| L3 | SWE-bench Verified/Pro, Terminal-Bench | 실제 저장소 이슈 해결·터미널 장기 과업 | 장기 자율성의 가장 성숙한 대리 지표 |

**각 벤치마크에서 수집할 항목**: ① 최고 점수와 모델/에이전트 이름 ② 사람 기준선(있으면) ③ 12개월 전 최고 점수(추세) ④ 과업당 평균 비용·단계 수(공개된 경우) ⑤ pass^k 또는 반복 신뢰도 ⑥ 리더보드 조회 날짜 ⑦ 알려진 오염·포화 논란.

**출력물**: 벤치마크 × (최고 / 사람 / 1년 전 / 오픈 모델 최고) 표 1장 + 추세 도식 1장.

### 2.2 플레이어 지도(정성)

세 층으로 나눠 수집한다.

- **모델 공급사**: Anthropic · OpenAI · Google · Meta · xAI · Mistral · Alibaba(Qwen) · DeepSeek · Moonshot 등 — 각사의 에이전트 전용 기능(도구 호출·컴퓨터 사용·장기 과업 모드)과 공개된 벤치마크 자기 보고.
- **에이전트 제품**: 코딩 에이전트(터미널·IDE·클라우드형), 컴퓨터/브라우저 사용 에이전트, 범용 소비자 비서, 기업 업무 자동화 플랫폼 — 각각 자율성 레벨·배치·가격.
- **오픈소스 프레임워크·프로토콜**: LangGraph · OpenAI Agents SDK · CrewAI · AutoGen/AG2 · smolagents · Google ADK · Pydantic AI 등 프레임워크, MCP(Model Context Protocol) · A2A(Agent-to-Agent) · 함수 호출 JSON 스키마 등 프로토콜 — GitHub 스타·릴리스 주기·채택 사례.

**성숙도 판정 3단계**: 표준화됨(복수 공급사가 같은 규격 채택) / 사실상 표준(한 규격이 지배적) / 난립(경쟁 중, 호환 없음). 블록별(1.3)로 판정표를 만든다.

### 2.3 온디바이스·오픈 가중치 모델(정량)

- **대상**: 1~30B급 오픈 가중치 모델 후보 — Qwen3 계열, Gemma 3/3n, Llama 계열, Phi-4(-mini), LFM2, SmolLM, gpt-oss 등. 조사 시 2026-11 기준 최신 세대로 갱신.
- **수집 항목**: 도구 호출 점수(BFCL 등), 파라미터 수, 양자화(4·8비트)별 메모리, 하드웨어 급별 tokens/s(소비자 GPU 1장 / 노트북 CPU·NPU / 엣지 보드), 라이선스, 지원 언어(한국어 포함 여부).
- **로컬 실행 스택**: Ollama · llama.cpp · vLLM · MLX · ONNX Runtime — 함수 호출 지원 여부, 스트리밍, 하드웨어 백엔드.
- **출력물**: "클라우드 최고 vs 오픈 모델 최고 vs 온디바이스 실용"의 격차표.

### 2.4 정성 한계 축

| 한계 | 어떻게 확인하나 |
|---|---|
| 신뢰도 | pass^1 → pass^k 하락 폭(같은 과업 반복 시 흔들림), 벤치마크 분산 |
| 환각·과업 포기 | 평가 논문의 실패 유형 분류, 각사 시스템 카드 |
| 안전성 | 프롬프트 인젝션·도구 오남용 벤치마크와 공개 사고 사례, 권한·확인 설계 |
| 장기 과업 실패 양상 | 루프 빠짐·목표 이탈·문맥 한계 — 코딩·컴퓨터 사용 사례 분석 |
| 비용 | 과업당 토큰·달러, 비용 폭주 사례 |

## 3. 2부 — 음성 에이전트: 구성·오픈소스·수준

### 3.1 구성 두 갈래

**(A) 캐스케이드 파이프라인** — 블록을 이어 붙이는 전통적 구성. 각 블록을 교체할 수 있고 디버깅이 쉽다. 지연은 블록 지연의 합이므로 **스트리밍**(ASR 부분 결과·LLM 토큰 스트림·문장 단위 TTS)과 **턴 관리**(엔드포인팅: 말이 끝났는지 판정, barge-in: 사용자가 끼어들면 즉시 멈춤)가 체감 품질을 결정한다.

```
 마이크 ─▶ VAD(발화 검출) ─▶ ASR(음성→텍스트) ─▶ LLM(+도구 호출·메모리) ─▶ TTS(텍스트→음성) ─▶ 스피커
            │                                                                    ▲
            └── 턴 관리(엔드포인팅 · barge-in) ──────────────────────────────────┘
 지연 예산 = VAD 판정 + ASR 마무리 + LLM 첫 토큰(+도구 호출 왕복) + TTS 첫 음성 + 전송
```

**(B) speech-to-speech 단일 모델** — 오디오를 직접 입력받아 오디오를 출력하는 모델. 전이중(듣는 동안 말하기)과 운율·감정 전달에 강하고 지연이 짧지만, 도구 호출·사실성·제어 가능성은 조사로 확인할 항목이다.

조사 시 각 상용 제품(OpenAI Realtime 계열·Gemini Live·Alexa+·Siri·Copilot 음성 등)이 어느 갈래인지, 혼합형(음성 이해는 네이티브, 출력은 TTS 등)인지 표로 정리한다.

### 3.2 블록별 오픈소스 후보

조사 시 각 후보의 **라이선스 · 한국어 지원 · 스트리밍 지원 · 실행 요구(CPU만/GPU) · 최근 릴리스일**을 확인해 표를 완성한다. 아래는 후보 목록이다.

| 블록 | 오픈소스 후보 | 확인할 것 |
|---|---|---|
| VAD·턴 검출 | Silero VAD, WebRTC VAD, 스마트 턴 검출 모델(의미 기반 엔드포인팅) | 오탐·지연, CPU 부하 |
| ASR | Whisper(faster-whisper·whisper.cpp), NVIDIA Parakeet/Canary, Moonshine, Kyutai STT, Vosk | WER(영·한), 스트리밍, 실시간 배율 |
| LLM 로컬 실행 | Ollama · llama.cpp · vLLM + 2.3의 오픈 모델 | 함수 호출 지원, 첫 토큰 지연 |
| TTS | Kokoro, Piper, Chatterbox, Coqui XTTS, Orpheus, Kyutai TTS, Fish Speech | 첫 음성 지연, 자연성, 한국어 음성 |
| speech-to-speech 오픈 | Moshi(Kyutai), Ultravox, Qwen-Omni 계열, Sesame CSM | 전이중 여부, 도구 호출 가능성, 요구 VRAM |
| 오케스트레이션 | Pipecat, LiveKit Agents, Vocode, Rasa, OpenAI Agents SDK(voice), NVIDIA Riva/ACE | 블록 교체 용이성, 계측 훅, 커뮤니티 |
| 전송·입출력 | WebRTC(LiveKit·Daily), WebSocket, 로컬 마이크/스피커(sounddevice 등) | 네트워크 지연, 에코 제거 |

**출력물**: 블록 × 후보 비교표 + "완전 로컬 조합 / 하이브리드 조합 / 클라우드 조합" 3가지 레퍼런스 스택 제안.

### 3.3 음성 정량 지표

| 지표 | 정의 | 출처 |
|---|---|---|
| WER(단어 오류율) | ASR 오류 비율. 영어(LibriSpeech·Common Voice 등)와 **한국어 데이터셋 존재 여부** 확인 | 🔍 모델 카드, 📄 리더보드 |
| 왕복 지연 | 사용자 발화 끝 → 에이전트 첫 음성. 통념상 목표치와 상용 제품 공개치, 제3자 실측 비교 | 🔍(주장) · 📄 · 자체 측정 |
| TTS 자연성 | MOS(주관 평가), TTS Arena류 선호도 | 📄 · 💬 |
| 음성 에이전트 벤치마크 | VoiceBench, Big Bench Audio 등 — 음성 입력에서의 지시 이행·추론 | 📄 |
| 끼어들기·턴 처리 | barge-in 반응 시간, 잘못된 끊김 비율 | 자체 측정 위주 |

### 3.4 상용 음성 비서·플랫폼 수준

- **소비자 비서**: Alexa+ · Gemini(모바일·스피커) · Siri · Copilot 음성 — 구성 갈래, 공개 지연, 에이전트 기능(예약·구매 등 L2 과업) 범위, 가격.
- **전화 응대 에이전트**: 콜센터형 음성 에이전트 플랫폼 — 처리율·이관률 공개치.
- **개발자 플랫폼**: OpenAI Realtime, ElevenLabs Agents, Deepgram, Vapi, Retell 등 — 분당 가격, 공개 지연, 전이중·barge-in 지원.

## 4. 3부 — 직접 구현 트랙: 음성 에이전트 하나 만들며 자체 기준선 얻기

### 4.1 목표

3.1의 **구성(A)를 오픈소스로 끝까지 조립**해 실제로 대화하고, 블록별 지연·WER·자원 사용을 측정해 스코어카드(5.1)에 **"자체 구현" 열**을 추가한다. 문헌 수치만으로는 알 수 없는 "지금 오픈소스로 혼자 만들면 어디까지 되는가"를 몸으로 확인하는 것이 목적이며, 하드웨어 요구 사양(5.4)의 실측 근거가 된다.

### 4.2 단계 설계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **S1 최소 동작** | 오케스트레이션(Pipecat 또는 LiveKit Agents) + Silero VAD + faster-whisper + 로컬 LLM(Ollama, 4~8B급) + Kokoro 또는 Piper. 로컬 마이크·스피커. 모든 턴을 텍스트 로그로 저장 | 말로 묻고 음성으로 답을 받는다 |
| **S2 에이전트화** | 도구 2~3개(현재 시각·날씨·로컬 파일 검색 등) 함수 호출 + MCP 서버 1개 연결 + 대화 내 단기 메모리 | 도구가 필요한 요청을 성공시킨다(성공률 기록) |
| **S3 실시간성** | 스트리밍 ASR, 문장 단위 TTS, barge-in. 블록 경계마다 타임스탬프를 찍는 계측 코드 | 블록별 지연 p50/p95 표가 나온다 |
| **S4 비교** | ① 완전 로컬 ② 한 블록씩 클라우드 API로 교체(ASR·LLM·TTS) ③ speech-to-speech 오픈 모델(Moshi 등) — 같은 발화 세트로 지연·품질 비교 | 3구성 비교표 |

### 4.3 측정 항목

- 블록별 지연 분포(p50/p95): VAD 판정 · ASR 마무리 · LLM 첫 토큰 · 도구 호출 왕복 · TTS 첫 음성
- 왕복 지연(발화 끝 → 첫 음성)
- WER: 영어·한국어 소규모 발화 세트(각 50~100문장, 직접 녹음 또는 공개 데이터 일부)
- 도구 호출 성공률(S2 과업 20~30개)
- 자원: VRAM/RAM 사용량, GPU 점유율, 가능하면 전력
- 정성: 끊김·오탐·어색한 턴 전환 사례 기록

### 4.4 실행 환경 선택지 (사용자 결정 필요)

| 환경 | 가능할 것으로 보는 조합 | 제약 |
|---|---|---|
| 개발 PC(소비자 GPU 1장) | S1~S4 전부. 8B급 LLM + Whisper 중형 + TTS 동시 적재 | GPU 메모리에 따라 모델 크기 조정 |
| 노트북(GPU 없음·CPU/NPU) | S1~S3를 소형 모델(1~4B, Whisper 소형, Piper)로 | 지연이 길어질 가능성, S4의 Moshi는 어려울 수 있음 |
| 엣지 보드(GPU 있는 SBC) | S1~S3 소형 조합, 전력 측정 가능 | 설치·드라이버 비용 |
| 클라우드 GPU 임대 | S4 비교 실험만 | 마이크 입출력은 로컬에서 WebRTC로 연결 필요 |

조사 시작 전에 환경을 정하고, 계획서 다음 판에 사양을 기록한다.

### 4.5 산출물

`implementation/` 폴더 — 코드, 설치 방법, 측정 스크립트, 발화 세트, README. 측정 결과는 `measurement.md`와 종합 보고서(5장)에 반영한다.

### 5.2 정성 성숙도 매트릭스

1장 분류 셀(자율성 × 모달리티 × 배치) × 성숙도 5단계 — **연구 / 데모 / 얼리 제품 / 보급 / 상품화 완료** — 히트맵 1장. 구성 블록(1.3)별 표준화 판정표를 함께 둔다.

### 5.3 연구 주제 후보

스코어카드의 열 간 격차(최고 vs 실용, 클라우드 vs 로컬, 문헌 vs 자체 구현)와 한계 축(2.4)에서 비어 있는 칸을 후보로 뽑는다. 각 후보에 "왜 비어 있나 · 무엇을 재면 되나 · 필요한 장비"를 붙인다.

### 5.4 하드웨어 요구 사양

자율성 레벨 × 배치별로 메모리·메모리 대역폭·연산·지연 예산 표. 3부 실측(자원 사용·지연)과 2.3 모델 카드 수치를 근거로 한다.

### 5.5 경영 보고용 요약판(1~2쪽)

핵심 숫자 10개(출처·날짜 병기) + 시사점 5개 + "1년 전 대비 변화" 한 단락 + "아직 과장인 것" 한 단락.

### 5.6 후속 확장 자리

차량 콕핏 등 특정 도메인 응용은 이 기준선 위에 **별도 편**으로 둔다. 본편에서는 도메인 전용 제품을 다루지 않는다.

## 8. 열린 질문 (사용자 결정 필요)

1. **구현 트랙 실행 환경** — 4.4의 네 선택지 중 무엇으로 할지, 보유 GPU·메모리 사양.
2. **완전 로컬 고집 vs 클라우드 API 혼용 허용** — S1~S3을 전부 로컬로 할지, S4에서만 API를 쓸지.
3. **한국어 비중** — 한국어 WER·한국어 TTS를 필수 축으로 둘지, 영어 중심에 한국어 부록으로 둘지.
4. **중국계 모델·제품 포함 범위** — Qwen·DeepSeek·Moonshot 등 오픈 모델은 포함이 자연스럽지만, 소비자 음성 비서까지 넣을지.
5. **리더보드 고정 날짜** — P1 시작일로 고정하고 P4까지 갱신하지 않을지, P4에서 한 번 더 갱신할지.
